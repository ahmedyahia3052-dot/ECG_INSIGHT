# Explainability Engine

## Overview

Every diagnosis produced by the Medical Intelligence Engine includes a full **explainability artifact** documenting why the diagnosis was chosen, what evidence supports it, what conflicts exist, what data is missing, and what alternatives should be considered.

**Source:** `server/src/modules/medical-intelligence/explainability/engine.ts`

---

## Explainability Artifact Schema

```typescript
interface ExplainabilityArtifact {
  diagnosisCode: MedicalDiagnosisCode;
  diagnosisLabel: string;
  rationale: string;                    // Why this diagnosis was selected
  supportingEvidence: string[];         // Features that support the diagnosis
  conflictingEvidence: string[];        // Features that argue against it
  missingEvidence: string[];            // Data needed for higher confidence
  possibleAlternatives: Array<{
    code: MedicalDiagnosisCode;
    label: string;
    reason: string;
  }>;
}
```

---

## Rationale Generation

The rationale combines:

1. **Rule identification** — Which rule fired (e.g., RHY-004)
2. **Trigger features** — What measurement features activated the rule
3. **Top supporting evidence** — Up to 3 strongest evidence items
4. **Conflicts** — Up to 2 conflicting features if present
5. **Gaps** — Up to 2 missing data points

**Example:**
> Atrial Fibrillation was selected by rule RHY-004 based on irregular_rhythm, heart_rate. Key supporting evidence: Rhythm: Irregularly irregular; Heart Rate: 110 bpm; RR variability: 22%. Additional data needed: Prolonged rhythm strip to confirm irregularly irregular pattern.

---

## Supporting Evidence

Extracted from rule evidence where `met: true`:

```
Heart Rate: 110 bpm (threshold: > 90 bpm)
Rhythm: Irregularly irregular
RR variability: 22% (threshold: > 15%)
```

Each item includes the measured value and applicable threshold when defined.

---

## Conflicting Evidence

Automatically detected conflicts:

| Finding | Conflict Detection |
|---------|-------------------|
| AF | Rhythm classified as regular |
| NSR | Heart rate > 100 bpm |
| STEMI | ST elevation below 1 mm threshold |
| LBBB | Axis not consistent with typical LBBB |
| Any rhythm finding | Competing rhythm findings from other rules |

---

## Missing Evidence

Context-aware gap detection:

| Finding | Missing Data |
|---------|-------------|
| AF | Prolonged rhythm strip |
| WPW | Delta wave confirmation in multiple leads |
| PE | Clinical pretest probability and imaging |
| STEMI/NSTEMI | Serial troponin, prior ECG comparison |
| Ischemia (low quality) | High-quality multi-lead ST analysis |

Additionally, diagnostic criteria from the knowledge base not covered by current evidence are flagged.

---

## Possible Alternatives

Sourced from:

1. **Knowledge base differentials** — Listed differential diagnoses for the finding
2. **Concurrent findings** — Other detected findings in the same category
3. **Cross-reference** — Matching labels in the differential list

---

## Explainability Summary

A report-level summary is generated from the primary finding's explainability artifact:

```typescript
function buildExplainabilitySummary(artifacts: ExplainabilityArtifact[]): string
```

Included in every `MedicalIntelligenceReport.explainabilitySummary`.

---

## Differential Diagnosis (Module 5)

While explainability covers immediate alternatives, the **Differential Engine** provides ranked top-5 lists:

```typescript
interface DifferentialDiagnosisEntry {
  rank: number;              // 1–5
  code: MedicalDiagnosisCode;
  label: string;
  likelihood: number;        // 0.0 – 1.0
  distinguishingFeatures: string[];
  explanation: string;
}
```

Ranking considers:
- Knowledge base differential list
- Concurrent rule findings in same category
- Raw confidence scores
- Category-related diagnoses as fillers

---

## Warnings

Special clinical warnings generated by the report engine:

- Low measurement confidence
- Multiple competing rhythm interpretations
- **CRITICAL:** WPW with AF — avoid AV nodal blockers
- LBBB with STEMI — apply modified Sgarbossa criteria
- No automated findings — clinical correlation essential

---

## API Access

Explainability is embedded in every finding within the report:

```
POST /api/medical-intelligence/analyze
→ report.findings[].explainability
→ report.explainabilitySummary
```

Stored in database as `explainabilityJson` on `MedicalDiagnosisFinding`.
